# Delivery checkout quotes

Checkout step 2 offers pickup or delivery from one branch. Delivery uses either an owned saved address or a new address entered inline (optionally saved at approved order placement); the backend revalidates its Shipment region chain. An existing default address is selected automatically unless the customer changes destination. Server-derived current cart prices, quantities, SKU parcels and local branch origin remain authoritative. No browser-provided weight, price, courier fee or recipient region is trusted.

`POST /api/checkout/delivery-quote` requires an onboarded store session and strict body `{ itemIds: string[], addressId: string }` **or** `{ itemIds: string[], newAddress: ClientAddressInput }`. Quoting a new address never writes it to the book; `saveAddress` is only considered during final approved order placement. Successful response is `{ success: true, data: { services } }`; each service has courier/service IDs, name, `shippingCost`, pricing strings, and optional valid ETA. Missing/foreign resources return 404, invalid/unready data 400, failed/no-service quote 502. No quote ID, TTL, background refresh or zero/stale fee fallback is invented.

The separate server-side Shipment adapter uses `JUBELIO_SHIPMENT_URL`, `JUBELIO_SHIPMENT_CLIENT_ID`, and `JUBELIO_SHIPMENT_CLIENT_SECRET`. It obtains a token through `/auth/generate-token`, respects token expiry, and posts measured per-item quantities/grams/cm to `/rates/all`. Rates requests send zip/area and measurement fields only, not recipient contacts or an invented carton. There is no retry/live fallback. E2E mode requires a bare HTTP loopback origin and is prohibited by either APP_ENV or NODE_ENV production. Logs never contain tokens, addresses or raw provider responses.

The customer pays exactly vendor **rates**, never **final_rates**. Delivery PPN is calculated on goods plus shipping using the existing website rate/rounding. For goods Rp100,000, rates Rp20,000 and PPN 11%, PPN is Rp13,200 and total Rp133,200 even if final_rates is Rp10,000. Nonempty opaque insurance_info is excluded until vendor semantics are known; shipping_insurance amounts alone are not interpreted as mandatory insurance. ETA is optional. No insurance premium is added.

Address/cart fingerprint changes discard service selection and displayed quote money, disable continuation and request fresh options. Late responses are discarded. The customer must select a service again. Failure offers retry or pickup. Both summaries use the selected server pricing, not stale cart prices; without a selected delivery service, totals are withheld.

Delivery order placement revalidates the quote and freezes immutable snapshots; see [delivery orders](delivery-orders.md). Booking reconciliation is a subsequent slice. Pickup remains functional.

Verification: browser mock E2E additionally exercises an inline unsaved address, default selection and the saved/unsaved order snapshot. delivery-quote.test.ts covers rates/final_rates, insurance metadata, cross-branch rejection and bad/empty provider results. jubelio-shipment-client.test.ts covers runtime gates, expiry, documented request shape and no retry. delivery-quote-mock.spec.ts covers quote money, address/quantity invalidation, failure and a server price change in both summaries. All provider traffic in these tests is loopback-only.
