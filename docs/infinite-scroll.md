# Infinite Scrolling — `/products` Storefront

## Overview

The storefront catalog page (`apps/store/src/app/products/page.tsx`) uses
**infinite scrolling** instead of numbered page links. The first **20**
products are rendered server-side (SSR); subsequent pages are fetched and
appended client-side as the user scrolls toward the bottom of the list.

## How it works

- **SSR first page** — `products/page.tsx` is a Server Component. It calls
  `/api/products?page=1&limit=20` with the active URL filters and passes the
  results to `<InfiniteProductGrid>` as `initialProducts` + `initialPagination`.
  This keeps the first paint fast and crawlable.
- **Client-side append** — `apps/store/src/components/InfiniteProductGrid.tsx`
  is a `"use client"` component. It holds the accumulated product list in state
  and renders a sentinel `<div>` at the bottom of the grid. An
  `IntersectionObserver` (with `rootMargin: "300px"` so loading starts slightly
  before the sentinel is visible) watches that sentinel; when it intersects and
  there are more pages, it fetches the next page from
  `/api/products?...&page=N&limit=20` and appends the result.
- **Reset on filter/sort change** — the parent passes
  `key={JSON.stringify(searchParams)}`. When the URL filters or sort order
  change, `ProductFilters` pushes a new URL, the server component re-renders
  with a fresh first page, and the `key` change remounts the grid so the
  accumulated list and pagination state start clean (no stale appended pages
  from the previous filter).

## Footer states

- **Loading** — `Loader2` spinner + "Memuat lebih banyak produk..." while a
  page is in flight.
- **End of list** — "Semua {n} dari {total} produk telah ditampilkan" once the
  last page has been appended and no more pages remain.
- **Empty** — "Tidak ada produk yang ditemukan." with a "Lihat Semua Produk"
  link when the first page returned zero products.

## API

No endpoint was added and no behavior changed. `/api/products` continues to
accept `page` + `limit` and return the `pagination` object
(`{ page, limit, total, totalPages }`). The page sends `limit=20`; the API's
default `limit` (12) is unchanged.

## Testing data

The seed (`packages/db/src/seed.ts`) was expanded from 10 to **50** products
(40 generated by `buildGeneratedProducts`) so the scroll behavior is
exercisable without manual data entry. Reproduce with:

```bash
npm run db:reset && npm run db:seed
```

## Verification

1. `npm run dev:store` → open `http://localhost:3000/products`.
2. First paint shows 20 cards; DevTools Network shows a single
   `/api/products?...page=1&limit=20` call.
3. Scroll to the bottom → a `page=2&limit=20` request fires automatically
   (cards 21–40 append); scroll again → `page=3` (41–50) appends and the
   end-of-list footer appears.
4. Apply a filter (e.g. category "Sneakers") → the grid resets to page 1 of the
   filtered set and scrolling resumes within that filtered result.
